# 도로 경로·거리·시간·품질 인계 확장 계획

작성일: 2026-11-15. 상태: 아래는 구현 전 계획 기록이며, 실제 결과와 수정된 라우팅 의미는 [도로 경로 취득 방법](research/SELECTED_ROUTES_METHOD.md)을 우선한다. 24개 대표 방향 구간의 실제 응답을 확보했으나 전체 행렬 구축은 완료하지 않았다. 기준은 [AGENTS.md](../AGENTS.md), [오케스트레이션](../ORCHESTRATION.md)이다. 모델 구현·학습·노선 성능 실험과 신규 비용은 제외한다.

## 1. 목표와 범위

사용자가 지정하거나 외부 모델 담당자가 이미 정한 정류장 방문 순서를 입력받아, 순서를 바꾸지 않고 해당 방향의 도로 경로 좌표·거리·추정시간·품질 근거를 같은 버전으로 제공한다. 지도 표시와 학습 이동 비용이 같은 경로를 참조할 수 있게 만드는 것이 목적이다. 우리 코드가 방문 순서를 최적화하지 않는다.

우선 목표는 **선택 구간의 도로 기반 표시와 재사용 가능한 경로 자료**다. 별도 목표인 464개 전 방향 214,832쌍의 완전한 비용 행렬을 완료했다고 표현하지 않는다. 기존 292개 부분 비용 자료를 새 경로와 자동으로 혼합하지 않는다.

## 2. 중요한 의미 수정: 최단거리와 최단시간은 다르다

OSRM의 Route는 주어진 순서에서 가장 빠른 경로를 구한다. Table의 거리 역시 기본적으로 가장 빠른 경로가 지나간 거리이며 거리 최소 경로와 같다는 보장은 없다. 따라서 새 자료는 `OSRM 자동차 프로파일의 최소 시간 기준 경로`로 명명한다. 기존 OSM 거리최단경로와 다른 목적·시점·프로파일일 수 있다.

실제 응답 후 보완: 사용한 서버의 `weight_name`은 `routability`이며 24개 중 1개에서 weight와 duration이 다르다. 구현의 목적 표시는 자동차 프로파일 가중 경로로 바꾸고 시간·거리 최소를 검증했다고 표현하지 않는다. 아래 최단시간 언급은 API 문서 확인 당시 계획이며 실제 자료의 해석은 원천 응답과 취득 방법을 따른다.

같은 응답의 geometry·distance·duration을 함께 저장하고 지도도 그 geometry를 그린다. 지도는 새 경로, 학습 비용은 기존 다른 경로 거리로 연결한 뒤 일치한다고 주장하지 않는다. 기존 비용과 비교할 때에는 별도 필드와 차이·버전을 기록하며 수치를 덮지 않는다.

근거: [OSRM 공식 API: Route·Table·RouteLeg](https://project-osrm.org/docs/v5.24.0/api/).

## 3. 단계별 작업과 통과 조건

| 단계 | 담당 | 작업 | 통과 조건 |
| --- | --- | --- | --- |
| 1. 경로 의미와 범위 확정 | B·E, C 검토 | 자동차/버스, 시간/거리 기준, 정차 위치, 원본 버전과 단위 명시 | 새 경로의 목적과 기존 자료 차이가 명세에 드러남 |
| 2. 무료 서비스 적합성 확인 | D | 공개 서버 정책·한국 구간 제공·응답 형식·실패 처리를 소수 요청으로 확인 | 실제 성공 응답 확보; 미확보면 가능성 확인과 취득 성공을 구별 |
| 3. 대표 구간 소규모 취득 | D·F | 서로 다른 12개 정류장 쌍의 양방향, 최대 24개 경로를 우선 저장 | 방향별 geometry·거리·시간·스냅 및 원문 응답 확보 또는 개별 실패 상태 보존 |
| 4. 품질·일관성 검증 | D·C | 아래 품질 기준과 선택 구간 원문 대조, 개별 경로 연속성 확인 | 오류와 미확인을 감추지 않고 구간별 결과를 설명 가능 |
| 5. 지도 연결과 오프라인 재사용 | F | 직선을 저장된 도로선으로 대체하고 실제 경로 비용·추정시간·경고 표시 | geometry 없는 구간은 도로 경로로 표시하지 않음; 캐시 자료로 재현 가능 |
| 6. 인계·리포트·공개 | A·C | 코드·설정·캐시·출처·검증·연구일지, 모델 연결 지침 정리 | C 검토 후 저장소 main 반영; 취득 범위와 잔여 공백 명시 |

대표 구간은 연대앞–역 주변, 북부 확장 지역, 가까운 반대편 정류장, 큰 우회·일방통행, 원본 0m 스냅 쌍, 단지 내부 접근 등 서로 다른 품질 문제를 포함하도록 고른다. 이는 후보를 12쌍으로 줄인 학습 문제가 아니라 도로자료 취득 방법의 검증 표본이다.

공개 데모 서버는 합리적인 비상업적 사용·초당 1요청 이하·가용성 비보장 조건을 명시한다. 계획에서는 요청 간격 2초 이상, 직렬 처리, 성공 결과 캐시, 요청 총량 제한을 적용한다. 429가 오면 해당 회차를 멈추고 무제한 재시도·프록시 우회를 하지 않는다. 214,832쌍을 공개 서버에 일괄 요청하지 않는다. 향후 대규모 행렬은 무료로 확보한 도로망과 로컬 처리 가능성을 따로 검토하며 비용을 새로 발생시키지 않는다.

근거: [OSRM 데모 서버 정책](https://github.com/Project-OSRM/osrm-backend/wiki/Demo-server). 1요청/초 제한은 허용 상한이지 대규모 자료 수집을 포괄적으로 허용한다는 뜻이 아니다.

## 4. 인계 데이터 형식

아래 경로는 구현할 때 사용할 제안이며 아직 생성하지 않았다.

```text
data/routes/v1/routes.geojson          # 지도용 경로
data/routes/v1/route_metrics.csv       # 구간별 거리·시간·상태·품질
data/routes/v1/manifest.json           # 버전·프로파일·원천·해시·가용 범위
data/routes/v1/responses/              # 재현 가능한 응답 캐시
scripts/fetch_selected_routes.py       # 제한·캐시·실패 처리를 갖춘 취득
scripts/validate_route_geometry.py     # geometry·스냅·메트릭 검사
```

각 구간의 핵심 필드:

| 필드 | 의미 |
| --- | --- |
| `route_id`, `from_station_id`, `to_station_id` | 순서가 있는 구간 ID와 방향 |
| `input_coordinates` | 원래 정류장 좌표, WGS84 경도·위도 순 |
| `snapped_coordinates`, `snap_distance_m` | 실제 경로 연결 지점과 정류장 간 오차, 출발·도착 각각 |
| `geometry` | GeoJSON LineString; 원본 응답의 전체 경로 |
| `distance_m`, `duration_s` | 동일 경로 응답의 거리·프로파일 추정시간 |
| `routing_objective`, `profile` | 예: fastest, car; bus 전용 검증과 구별 |
| `source`, `retrieved_at`, `data_version` | 제공처·취득 시점·제공된 지도 버전; 미제공이면 unknown |
| `request_parameters`, `cache_key`, `response_sha256` | 요청 조건·좌표·버전을 묶은 재현 근거 |
| `status`, `quality_flags` | 성공·no_route·no_segment·취득 실패·검토 필요를 구별 |
| `duration_kind`, `bus_feasibility_verified` | profile_estimate, false 등 실제 의미 |

품질은 검증되지 않은 확률 점수나 ‘신뢰도 95%’로 만들지 않는다. 관측 가능한 검사 결과와 미검증 항목을 나열한다. Route 응답에 Map Matching 서비스의 confidence 개념을 임의로 붙이지 않는다.

## 5. 품질 검사와 주의할 결합 문제

- 좌표 순서·범위, 방향별 ID, 유한·비음수 거리와 시간을 검사한다. 실패값을 0으로 대체하지 않는다.
- 원래 정류장 위치, 스냅 위치, geometry 시작·끝점을 대조한다. 스냅 오차가 크거나 같은 노드로 붕괴한 구간을 경고한다. 임계값은 사전에 명세하고 실제 분포와 함께 보고한다.
- 완전한 geometry의 구면 선분 길이와 API 거리, leg 합과 route 합을 비교한다. 반올림·표현 오차를 허용하되 큰 불일치를 검토한다. 자체 길이를 API 값 위에 조용히 덮지 않는다.
- A→B와 B→A는 별도 취득한다. 차이가 있다고 오류로 간주하거나 대칭화하지 않는다.
- 여러 개의 독립적인 두 점 경로를 이어 붙일 때는 B에서 도착·출발 스냅 위치와 진행 방향이 일치하는지 검사한다. 접근 방향이 다르거나 유턴이 필요할 수 있으므로, 단순 합이 실제 연속 운행을 보장하지 않는다.
- 외부 팀이 준 방문 순서를 다중 경유지 Route로 다시 요청하는 경우에도 순서는 바꾸지 않는다. 이어진 경로와 독립 구간 합이 달라지면 둘을 구분해서 보관하고, 학습 비용까지 자동으로 바뀐 것으로 처리하지 않는다.
- `duration_s`는 자동차 프로파일의 추정치다. 실제 07–09시 혼잡, 승하차 정차, 신호·대기·배차·운행시간 관측값이 아니다. 시간 변수를 얻었다고 기존 보상에 시간 패널티를 임의로 추가하지 않는다.
- 자동차 경로를 실제 마을버스의 정차·폭·중량·회전·유턴·진입 가능성 검증으로 표현하지 않는다. `approaches=curb` 등도 실제 정차 적합성을 인증하지 않는다.

## 6. 모델 담당자에게 연결하는 범위

지도와 소비자는 공통 `route_id` 및 버전으로 동일 geometry·거리·시간을 조회한다. 아직 취득하지 않은 구간은 캐시 부재로 남는다. 학습 도중 외부 공개 API를 매번 부르는 방식은 재현성·제한·속도 문제가 있으므로 기본안으로 삼지 않는다. 학습에 필요한 행동의 비용은 사전에 고정하거나 로컬에서 재현 가능한 자료로 제공해야 한다.

선택 경로의 데이터 완성은 전체 행동 공간의 비용 완성과 다르다. geometry가 몇 구간 있다고 전체 모델 준비 상태를 true로 바꾸지 않는다. 결측 행동 제외는 연구 문제 자체를 바꾸므로 외부 팀에게 범위 변화로 명시해야 한다. 기존 모델 입력은 유지하고 새 버전의 자료와 연결 지침을 제공하며, 학습 코드는 수정하지 않는다.

## 7. 현재 보상에 대한 실제 평가 관점의 재점검

평가 대상은 새 인계 명세의 `수요점수 + 0.5×신규 거점 − 0.2×km`다. 기존 모델의 기본 거점 +2와 혼동하지 않는다. 에이전트 C의 내부 판정은 실제 교수 승인이나 성적 보장이 아니다.

**방어 가능한 부분:** 하차 활동 대리 지표를 예산 제약 아래 수집한다는 목적은 수식으로 일관되며, 단위·학습 기준 정규화·최초 그룹 보너스·결측·종점 규칙을 명시했다. 이 목적의 단순한 학부 연구 기본안으로는 설명 가능하다.

**추가 방어가 필요한 부분:**

1. 하차량은 신규 노선 이용자나 OD 편익이 아니다. 목적을 실제 수송 효율로 확대하면 근거가 부족하다.
2. 0.5와 0.2, 반경 300m는 정책 가정이다. 신규 그룹 +0.5는 거리 비용으로 2.5km와 같으므로 작은 보너스라는 직관만으로 정당화하지 않는다.
   실제 비중앙차로·수요 관측 412개에서 수요 점수 중앙값은 약 0.015588이고, +0.5는 중앙값 정류장 약 32.08개분이다. 이 모집단의 최대 점수도 0.683970으로, 정규화 최대 1인 정류장은 중앙차로 제외 가정 대상이다. 따라서 ‘최대 점수의 절반이므로 수요 중심’이라는 과거 설명은 충분하지 않다. [독립 산술 근거](evidence/reward_tradeoff_audit.json).
3. 가까운 여러 정류장에 각각 점수를 주면 같은 생활권 접근을 반복해서 높게 평가할 수 있다. 거점 보너스 중복 방지와 정류장 하차 점수의 공간적 중첩은 별개다. 실제 승객 중복을 측정했다는 주장도 하지 않는다.
4. 추가 정차의 시간·운영비용이 없으므로 촘촘한 경유를 선호할 수 있다. 예를 들어 추가 100m 이동으로 수요 점수 0.2를 더 얻으면 거점 변화 없이도 보상 +0.18이다. 이것은 현 목적에 맞는 행동일 수 있지만 실제 운행 효율의 증명은 아니다.
5. 자유 종점·강제 계속 이동·자발적 종료 여부가 불분명하면 같은 수식으로도 다른 문제가 된다. 현재 모델은 유효 이동이 없어질 때 종료하므로 ‘더 이동하지 않기’를 선택할 수 있는 모델과 구별해 인계해야 한다.

계획 단계의 보완은 목적을 정확히 제한하고, 가중치의 등가관계를 설명하며, 중첩·과도한 정차·거점 우회·종료에 대한 작은 반례와 성질 검사를 추가하는 것이다. 역할 4에서 모델 성능 실험을 대신 수행하지 않는다. 외부 모델 담당자에게 가중치·거점 보너스 유무·후보 가정에 따른 비교 필요성을 전달한다. 지금 수식이 실제 교수 평가를 통과한다고 단정하지 않는다.

## 8. 이번 계획 이후의 구현 시작 순서

첫 구현 단위는 `최대 24개 방향별 대표 구간 → 같은 응답의 경로·거리·시간 저장 → 품질 보고 → 기존 지도 연결`이다. 보상 가중치나 학습 코드는 이 기능 구현에 편승해 변경하지 않는다. 이 소규모 단위의 가용성과 정확성을 확인한 다음 선택 구간 추가, 로컬 전체 비용 구축 가능성, 모델 담당자 연결을 순서대로 검토한다. 기존 main 자료는 보존하고 구현·검증 완료분을 다음 커밋으로 반영한다.
