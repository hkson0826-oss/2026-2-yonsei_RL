[정류장 지도](../output/role4/station_map.html), [데이터 인계와 재생성](ROLE4_HANDOFF.md), [통합 참조 JSON](../data/processed/role4_bundle.json)을 함께 제공한다. C3 검토는 **참조 지도 기능과 부분 데이터·설계 인계** 범위에서 통과했으며, 전체 모델 준비나 운행 검증 완료 판정이 아니다.

## 1. 연구 질문과 핵심 결과

연구 질문은 **서대문구 정류장을 충분히 포괄하면서, 오전 하차 실적·철도역 접근·방향별 도로비용을 어떤 규칙으로 연결해야 모델 담당자가 그 의미와 한계를 알 수 있는가**다.

기존 282개는 서대문구 전체 목록이 아니었다. 서울시 공식 정류장 자료의 ARS 지역 코드 `13`으로 추출한 목록은 464개다. 내부 NODE ID의 `112` 접두어만 사용하면 다른 접두어를 가진 서대문구 ARS 정류장 15개도 놓친다. 따라서 공식 코드 기준 464개를 지도 모집단으로 사용한다. 이는 2026-09-02 시점의 코드 기반 목록이며, 행정경계 폴리곤이나 현재 실제 운행 여부를 독립 검증한 목록은 아니다.

| 구분 | 확인 결과 | 해석 |

## 2. 선행연구에서 채택한 문제의식

[문헌 분석](research/LITERATURE_REVIEW.md)은 연구 논문 4편과 공식 접근성 지침 1개를 검토했다. 실제 읽은 절·서지·원문은 [서지 기록](research/literature_sources.json)에 남겼다.

- 가치 수집 경로 연구는 거리 예산 안에서 방문 지점의 점수를 높이는 구조를 설명한다. 현재 문제를 모든 정류장을 반드시 방문하는 문제로 간주하지 않는다.
- OD 기반 교통망 설계 연구는 승객 통행 편익과 운영비용을 구분한다. 우리에게 OD·배차·용량 정보가 없으므로 하차 실적 점수와 실제 신규 서비스 편익을 동일시하지 않는다.
- 접근거리 연구와 공식 지침은 직선 근접성, 보행 네트워크, 대기·빈도·환승 효과를 구별한다. 특정 도시의 반경을 서울의 최적 환승 반경으로 옮기지 않는다.

따라서 이번 설계는 **과거 하차 실적과 근사 거점 접근을 이용한 정류장 방문 가치**다. 실제 신규 탑승객 수, 고유 이용자 수, 환승 시간 절감, 노선 최적성은 입증하지 않는다.

## 3. 수요 정의와 확인된 차이

학습 수요의 의미는 2026년 5–8월 전체 요일의 오전 07–09시 일평균 하차 실적이다. 월별 노선·방향별 원천 행을 정류장 ID로 합산하고 07시대·08시대 하차량을 더했다. 5–8월은 총 123일이다.

```text
학습 일평균 = 5–8월 월간 하차량 합 / 123일
정규화 점수 = 학습 일평균 / 관측된 학습 모집단의 최대 일평균
```

최대 일평균은 약 847.789명/일이다. 분모는 관측된 학습 모집단 전체에서 정하며 필터·검증 월마다 다시 산출하지 않는다. 검증 점수가 1보다 커도 실제 수치는 자르지 않는다. 원천 행이 없으면 수요를 `null`로 유지한다.

기존 코드는 월별 일평균 4개의 단순평균을 사용했다. 기존 282개에서 두 평균의 최대 절대 차이는 약 0.679명/일, 상위 10개는 같았다. 산식을 통일해야 하지만 이 차이가 노선의 큰 변화를 설명한다고 단정할 근거는 없다. 확대된 454개에서는 실제 관측 0명이 있어 max-only와 min-max 정규화 값도 같다.

`weekday_avg_07_09_est`는 승하차 합계의 평일 추정치이므로 평일 하차량으로 사용하지 않는다. [수요 재집계 근거](../data/reference/ridership_provenance.json), [기존 산식 수치 비교](evidence/demand_definition_audit.json).

## 4. 거점·거리·보상의 설계 근거

거점은 공식 철도역 기준점과 연대앞 기준점으로 정의한다. 호선이 다른 동일 환승역은 그룹을 공유하고, 신촌 2호선과 경의중앙선 신촌은 구분한다. 직선거리 300m를 기본 스크리닝 반경으로 삼고 가장 가까운 그룹 하나에 귀속한다. 이는 실제 보행 경로나 서울 최적 반경을 검증한 값이 아니다.

전체 464개에서 반경을 200/300/500m로 바꾼 공간 검증 결과, 배정 정류장 수는 61/103/186개다. 500m에서는 복수 그룹 후보가 36개 발생한다. 최근접 단일 귀속으로 중복 보너스를 줄이는 대신 다중 접근성을 표현하지 못하는 한계가 있다. 기준점 후보가 있어도 다른 그룹에 더 가까우면 해당 거점에 배정되는 정류장이 없을 수 있다. [독립 계산](evidence/hub_radius_audit.json).

보상은 수요·신규 거점·도로거리 항을 분리한다. 기본 계수는 명세에서 정한 프로젝트의 정책 선호이며 문헌이 입증한 최적값이나 학습 결과가 아니다. 그룹별 최초 한 번 보너스를 주고 출발 그룹은 이미 방문한 것으로 처리한다. 모델 담당자는 인계 명세의 값·종료 조건·유효 행동을 일관되게 구현해야 한다.

도로 행렬은 정차 지점 사이 방향별 최단거리 비용이다. 인접 정류장만 연결한 그래프나 실제 버스 운행 적합성 인증이 아니다. 기존 비대각 0m 한 건은 같은 도로 노드에 붙은 스냅 근사로 설명되지만 원본값과 품질 경고를 보존한다. 회전·유턴·단지 내부 도로 및 정차 적법성은 미검증이다. [거리 방법과 한계](research/ROAD_METHOD.md).

## 5. 인계할 때 반드시 유지할 구분

1. 공식 464개 참조 목록, 수요 관측 집합, 도로 관측 부분 집합, 정차 정책에 따른 후보를 구별한다.
2. 중앙차로 제외는 연구 가정이며, 제외 정류장의 기록을 지도나 원본에서 삭제하지 않는다.
3. 292개 도로 완전 부분 집합은 진단·호환성용이다. 전체 지역의 최종 실험 후보로 바꾸어 부르지 않는다.
4. 기존 `train.py`는 수요를 다시 계산하므로 새로운 일평균·정규화 점수를 자동으로 사용하지 않는다. 모델 담당자의 명시적인 입력 연결이 필요하다.
5. 지도·자료의 완성과 전체 모델 준비·실제 운행 검증은 서로 다른 상태다.

## 6. 연구 근거와 남은 과제

상세한 질문·분석·수정된 해석은 [연구일지](research/RESEARCH_LOG.md)에, 단계별 과학적 검토는 [C 검토](research/REVIEWS.md)에 기록한다. [공간 감사](research/DATA_SPATIAL_AUDIT.md)와 [수요·보상 명세](research/DATA_REWARD_SPEC.md)를 함께 읽어야 한다.

남은 핵심 과제는 전체 464개에 일관된 도로거리 원천을 확보하고 재현 가능한 방향별 스냅과 비용을 구축하는 것이다. 원천 기록이 없는 10개 수요와 정류장 개폐·ID 이력, 역 출입구·보행 접근성도 후속 검토 대상이다. 이 제한 때문에 전체 노선 학습이 준비됐다고 결론 내리지 않는다. 모델 구현과 성능 비교는 외부 담당자의 범위이며 이번 연구 결과가 아니다.

## 7. 산출물 검증 범위

464개×6개월 원자료와 통합 값, CSV 결측, 원본 방향별 비용, 지도 내장 데이터의 일치를 독립 검토했다. Python 데이터·거리 의미 검사 16개와 오프라인 DOM 기능 검사 14개가 통과했다. 생성 SVG의 정적 그림도 별도로 확인했다. DOM 기능 검사는 검색·필터·월별 값·거점 반경·단일 이동 보상 산술을 확인한 것이며 실제 브라우저의 반응형 화면 배치를 검증한 것은 아니다. [지도 검사 근거](evidence/map_validation.json).
