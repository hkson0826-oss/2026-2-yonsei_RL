# 선택 구간의 실제 도로 경로·거리·시간·품질 자료

기준일: 2026-11-15. 범위는 [도로 경로 인계 계획](../ROAD_GEOMETRY_DELIVERY_PLAN.md)의 대표 구간 취득이다. 학습·정류장 순서 최적화·전체 지역 비용 완성·버스 운행 검증은 수행하지 않았다.

## 1. 연구 질문과 원천

선택한 실제 정류장 두 점을 도로망에 연결했을 때, 지도에 그릴 경로 좌표와 그 경로의 이동 비용을 같은 원문에서 재현할 수 있는가?

공식 ARS 13 정류장 464개의 위치를 유지하면서 서로 다른 품질 문제를 대표하는 12개 쌍을 사전에 정했다. 연대앞–역 주변, 독립문·무악재·홍제의 북부 확장, 반대편 정류장·다른 출구의 짧은 이동, 주거·아파트 구간, 기존 0m 스냅 쌍 등을 포함한다. 각 쌍은 양방향으로 요청해 총 24개 방향별 관측을 만들었다. 이 표본은 전체 464개를 대체하는 학습 후보 집합이 아니다.

원천은 공개 OSRM 데모의 Route 서비스다. 공식 문서는 주어진 좌표 순서의 빠른 경로와 GeoJSON·거리·추정시간 응답을 설명하며, 데모 정책은 합리적인 비상업적 사용, 초당 1요청 이하, 가용성·갱신 비보장을 명시한다.

- [OSRM 공식 API](https://project-osrm.org/docs/v5.24.0/api/)
- [OSRM 데모 서버 정책](https://github.com/Project-OSRM/osrm-backend/wiki/Demo-server)

실제 취득은 `router.project-osrm.org`, 자동차 driving 프로파일, `alternatives=false`, `geometries=geojson`, `overview=full`, `steps=true`, `approaches=curb;curb`로 수행했다. 모든 요청은 직렬이고 간격은 최소 2초이며 이미 취득한 결과를 캐시한다. 24개 이외 전체 방향별 조합을 요청하지 않았다. 429·접근 제한·서버 장애를 우회하거나 유료 서비스·API 키를 사용하지 않는다.

## 2. 산출물과 공통 의미

| 자료 | 내용 |
| --- | --- |
| [routes.geojson](../../data/routes/v1/routes.geojson) | 24개 성공 경로의 실제 GeoJSON LineString과 동일 응답의 거리·추정시간 |
| [route_metrics.csv](../../data/routes/v1/route_metrics.csv) | 모든 선정 구간의 관측·실패 상태와 단위·품질 필드 |
| [selection.json](../../data/routes/v1/selection.json) | 방향별 표본과 선택 이유, 원래 정류장 좌표·ID |
| [manifest.json](../../data/routes/v1/manifest.json) | 요청 조건·원천·수량·버전 의미·캐시 해시 |
| `data/routes/v1/responses/` | 각 구간 원문 응답 바이트와 시각·요청·해시 metadata |
| [검증 결과](../evidence/selected_routes_validation.json) | 좌표·방향·원문 일치와 품질 검사 |

좌표는 WGS84 **경도, 위도** 순이다. 같은 Feature의 geometry·distance_m·duration_s는 같은 응답에서 가져온다. 입력 좌표와 실제 스냅 좌표를 각각 보관하고, 스냅 오차를 독립적인 구면 거리로 계산한다. 실제 24개 응답의 `route_weight_name`은 모두 `routability`이므로 이를 원문대로 보존한다. 23개는 weight와 duration이 같지만 `112000073→112000125`는 weight 108.7, duration 88.5초로 다르다. 따라서 일반 API 설명의 ‘빠른 경로’를 엄밀한 시간 최소 보장으로 확대하지 않고 **자동차 프로파일의 경로 가중치에 따른 추천 경로**로 표기한다. 거리 최소 경로라고도 부르지 않는다.

이에 따라 각 경로와 manifest에 `minimum_duration_verified=false`, `shortest_distance_verified=false`를 명시한다. 경로에 부속된 추정시간이 관측되었다는 사실과 그 시간이 전체 가능한 경로 중 최솟값으로 독립 검증되었다는 주장은 다르다.

제공된 응답에는 지도 `data_version`이 없어 `null` 및 `provider_data_version_not_supplied`를 기록한다. 미래에 같은 URL을 다시 호출해 같은 결과가 나온다는 보장은 없다. 재현은 함께 보존한 응답과 SHA-256을 기준으로 한다.

## 3. 품질 검사

기하·수치 검사는 성공 응답을 차량 운행 인증으로 바꾸지 않는다. 아래 수치는 검토 대상을 찾기 위한 명시적 선별 규칙이며 확률적 신뢰도나 문헌이 정한 서울 버스 적합성 임계값이 아니다.

- 입력·스냅·경로 좌표의 순서·범위 및 방향별 정류장 ID를 확인한다.
- 거리·추정시간은 유한·비음수여야 한다. 관측 부재는 `null`이며 0과 구별한다.
- 정류장–스냅 거리가 30m 초과면 검토, 100m 초과면 큰 오차 검토로 표시한다.
- geometry 시작·끝과 스냅 위치의 차이가 3m를 넘으면 경고한다.
- 구면 선분 길이와 API 거리의 차이가 `max(5m, API 거리의 2%)`를 초과하면 검토한다. 실제 API 값을 자체 계산으로 덮지 않는다.
- leg의 합계와 route의 거리·시간이 1m/1초보다 크게 다르면 검토한다.
- 서로 다른 입력 정류장이 같은 스냅으로 붕괴하거나 비대각 거리 0이면 원본값과 경고를 함께 보존한다.
- raw 응답 해시, 원문 geometry·거리·추정시간·스냅 좌표가 공개 산출물과 정확히 일치하는지 다시 확인한다.

## 4. 실제 결과

24개 방향별 요청 모두 경로 좌표를 반환했다. 정한 기하·수치 선별 임계값을 넘은 경로는 없었다. 가장 큰 재계산 스냅 오차는 약 16.00m, geometry 구면 길이와 API 거리의 최대 절대 차이는 약 3.135m다. 이 결과가 보행·정차·버스 회전 검증 통과를 뜻하지는 않는다.

연세대학교앞 `112000031 → 신촌전철역 112900230`은 1,517.8m, 118.3초의 자동차 프로파일 경로를 반환했다. 지도에서는 이 응답의 도로 좌표를 사용해야 하며, 정류장 간 직선이나 다른 원천의 거리로 바꾸어 같은 경로라고 설명하면 안 된다.

기존 원본의 0m 쌍인 `112900003→112900157`은 이번 별도 버전에서 21.3m·8.7초, 역방향은 245.2m·50.8초다. 새로운 프로파일·지도 시점·스냅 조건의 결과이며 기존 값이 반드시 틀렸음을 독립 입증한 것은 아니다. 기존 292개 비용 행렬은 바꾸지 않았고 새 수치를 섞어 채우지 않았다.

## 5. 학습·운행 해석의 한계

- `duration_s`는 자동차 프로파일 추정시간이다. 실제 07–09시 혼잡, 버스 승하차·정차·배차·대기를 관측한 시간은 아니다.
- `approaches=curb`는 연결 조건일 뿐 버스 정차의 적법성·승강장 진입·횡단·회전·차량 폭이나 중량을 검증하지 않는다.
- 각 독립 두 점 경로를 이어 붙여도 중간 정류장의 도착·출발 방향·스냅 위치가 맞는다는 보장은 없다. 외부 팀의 고정 방문 순서를 별도 다중 경유지 요청으로 검토할 때에도 순서 최적화와 구별해야 한다.
- 24개 경로가 있다는 사실은 464개 전체의 비용 행렬 완성이 아니다. `full_district_model_ready=false`, `bus_feasibility_verified=false`를 유지한다.
- 학습에 쓰려면 모델 담당자는 같은 버전의 경로 비용을 고정해서 연결해야 한다. 학습 중 공개 API를 반복 호출하는 방식은 기본안으로 삼지 않는다. 새로운 시간 패널티나 보상 가중치도 이 자료 취득에 편승해 추가하지 않는다.

## 6. 재현과 추가 취득의 경계

저장소에 응답 캐시가 있으므로 아래 명령은 네트워크 없이 재생성·검증한다.

```powershell
python scripts/fetch_selected_routes.py --offline
python scripts/validate_route_geometry.py
python -m pytest tests/test_selected_routes.py -q
```

`--fetch`만 제한된 네트워크 취득을 허용한다. 동일 버전의 정상 캐시는 다시 요청하지 않으며, 요청 조건이 달라지면 별도 버전을 요구한다. 접근 제한·429·서버 장애로 중단한 기록이 있으면 같은 버전에서 자동 재시도를 재개하지 않는다. 표본이나 프로파일 확대는 정책·재현성·품질을 다시 검토한 별도 작업이다.
