## 1. 목적과 결론의 범위

제한된 노선 길이 안에서 정차 지점을 선택하는 모델에, 기존 하차 실적·거점 접근의 대리 지표·방향별 이동 비용을 제공한다. 이는 신규 탑승객 수, 고유 승객 수, OD 통행 완료율, 실제 환승 편익을 예측하는 명세가 아니다. 학습 알고리즘·노선 탐색·성능 비교는 모델 담당자의 범위다.

[선행연구 분석](LITERATURE_REVIEW.md)은 점수 수집 경로와 풍부한 OD 기반 교통망 설계의 차이를 설명한다. 실제 자료의 모집단·누락·방향성은 [공간 감사](DATA_SPATIAL_AUDIT.md)와 [도로 방법](ROAD_METHOD.md)에 근거한다. 특정 보상 계수나 직선 반경은 논문이 입증한 최적값이 아니라 아래에 이유를 명시한 프로젝트 가정이다.

## 3. 수요 정의

월 m의 정류장 i에 대해 `A(i,m)=alight_07+alight_08`이며 이는 오전 07:00–09:00의 월간 하차량 합계다. 09시대는 포함하지 않는다. 원자료는 노선·방향별 기록을 표준 정류장 ID로 합산한다. 원천 행이 있으면 합계 0도 실제 관측값이고, 원천 행이 없으면 0으로 추정하지 않는다.

학습 월은 `202605–202608`, 검증 월은 `202609–202610`이다.

```text
complete_train(i) = 4개 학습 월 모두 has_source_record=1
D_i = Σ_m A(i,m) / Σ_m calendar_days(m) = 학습 총하차량 / 123
M = max D_i over complete_train인 공식 기준 정류장 전체
d_i = D_i / M
```

학습 월 중 하나라도 원천 기록이 없으면 `D_i=null`, `d_i=null`이다. 부분 관측 월만으로 평균을 대체하지 않는다. M=0이면 관측된 정류장의 점수를 모두 0으로 두고 미관측은 계속 `null`이다. 음수·비유한 수요는 오류로 처리한다.

정규화 모집단은 중앙차로를 포함한 **학습 4개월 관측 공식 정류장 454개 전체**로 고정한다. 후보 필터·거점 반경을 바꿔도 M을 다시 계산하지 않는다. 현재 M은 `104278/123 = 847.7886178861788`, 정류장 `112000403` 서대문역이다. 이는 기존 코드의 월별 일평균 4개 단순평균과 다르다.

### 검증 월과 표시

```text
D_i,m = A(i,m) / calendar_days(m)
d_i,m = D_i,m / M  # 학습에서 계산한 같은 M
```

검증값은 1을 초과할 수 있고 잘라내지 않는다. 지도 점 크기·색 범위만 제한한다면 표시 제한임을 알리고 팝업에는 실제 값을 유지한다. 저장은 반올림하지 않고 출력 화면에서만 적절히 반올림한다.

기간 총량/총일수는 모든 날짜를 같은 비중으로 다루려는 통계적 정의다. max-only는 비율과 영점을 보존하며, 최소값 차감을 경유 정류장 수마다 추가하지 않으려는 선택이다. 확대된 관측 모집단에는 실제 0명인 정류장이 있어 min-max도 같은 수치를 주지만 정의는 max-only로 명시한다. 어느 논문이 이 산식을 서울에 최적이라고 입증했다고 해석하지 않는다.

모든 값에는 평일·주말·공휴일이 함께 들어간다. 원본의 `weekday_avg_07_09_est`는 승하차 합계의 평일 추정치이므로 이 명세의 하차량 보상에 사용하지 않는다.

### 원본부터 점수까지 추적 예

`112000403`의 5–8월 하차량은 각각 23,966 / 27,352 / 27,780 / 25,180명이다. 합계 104,278명을 `31+30+31+31=123`일로 나누면 약 847.789명/일이며, 고정 M으로 나눈 학습 점수는 1이다. 이 정류장은 중앙차로이므로 지도에는 남지만 비중앙차로 필터에서 제외된다. 그 필터를 적용해도 M은 유지한다.

## 4. 거점 정의와 매핑

공식 철도역 기준점과 연대앞 프로젝트 기준점을 사용한다. 현재 참조는 22개 기준점·16개 그룹이다. 환승역의 노선별 기준점은 같은 `hub_id`로 묶고, 신촌 2호선과 신촌 경의중앙선은 서로 다른 그룹이다. 연대앞은 공식 버스정류장 기준점 3개를 하나의 프로젝트 그룹으로 묶으며 측량된 교문이라고 하지 않는다.

철도역 좌표는 실제 출입구가 아니다. 경계 인근 역도 해당 공식 기준 정류장에서 반경 내라면 접근 후보가 될 수 있다. 이 반경은 직선 스크리닝이며 실제 도보·횡단·장벽·고저차·환승 가능성을 확인한 결과가 아니다.

### 결정 가능한 계산 규칙

1. WGS84 위·경도를 라디안으로 바꾸고 반지름 `6,371,008.8m`의 구면 haversine 거리를 계산한다.
2. 한 정류장에서 각 그룹까지 거리는 그 그룹의 모든 기준점까지 거리의 최솟값이다.
3. 그룹 거리 `<=300m`인 그룹을 모두 후보로 기록한다.
4. 그중 가장 가까운 **한 그룹만** `hub_id`로 배정한다. 거리가 정확히 같으면 `hub_id`, 같은 그룹 안의 기준점 동률이면 `anchor_id` 사전식 순서로 정한다.
5. 후보가 없으면 `hub_id=null`, 배정 거리도 `null`이다. 모든 반경 내 후보와 최소 거리 기준점은 별도 진단 필드에 보존한다.

중앙차로·수요 결측·거리 미확보 정류장에도 참조 매핑은 한다. 매핑 사실 자체를 정차 가능성이나 보상 계산 가능성으로 승격하지 않는다. 복수 그룹 보너스를 동시에 받지 않도록 단일 귀속을 기본안으로 삼으며, 가까운 여러 목적지에 접근할 수 있는 정보 손실은 후보 목록과 한계로 남긴다.

300m는 보행 자료가 없는 상황에서 근접성을 보수적으로 표현하기 위한 인계 기준이다. 200/300/500m에서 매핑 정류장 수·중첩 정류장 수·그룹별 배정 수·미연결 그룹을 비교한다. 이는 공간 자료·가정의 변화 분석이며 노선·모델 성능 실험이 아니다. 300m가 최적이라는 결론을 내리지 않는다.

[공간 반경 분석](../evidence/hub_radius_audit.json)의 실제 결과는 200m에서 61개 정류장·13개 배정 그룹·중첩 0개, 300m에서 103개·14개 그룹·중첩 0개, 500m에서 186개·14개 배정 그룹·중첩 36개다. 300m의 애오개·서강대 그룹은 배정 정류장이 없다. 500m에서는 두 그룹에 반경 내 후보가 있지만 다른 그룹이 더 가까워 최종 배정은 없다. 따라서 `반경 안 후보 없음`과 `단일 귀속 결과 배정 없음`을 서로 다른 지표로 저장한다.

## 5. 거리와 정차 가정

`data/processed/road_distances_full.json`의 `ids`와 464×464 `distances_m`를 사용한다. 기존 OSM 기반 연구 비용을 보존하고 방향을 대칭화하지 않는다. `null`은 이동 불가가 아니라 자료 미확보다. 대각선 0도 해당 정류장의 외부 도로자료가 있다는 뜻은 아니다.

원본 비대각 0m인 `112900003→112900157`은 값과 경고를 함께 보존한다. 같은 스냅 노드라는 설명은 실제 정차 위치의 이동이 0m라는 증명이 아니다. 이를 임의 1m로 바꾸지 않으며, 외부 담당자가 수요/거리 비율을 쓴다면 `max(distance,1m)` 등의 분모 보호값은 거리 원자료 보정과 구별해서 정해야 한다.

기준 목록의 `중앙차로` 42개는 비중앙차로 분석 필터에서 제외한다. 이는 원래 프로젝트의 정차 후보 가정이며 법적 정차 불가 판정이 아니다. 스냅 `check`·`unverified`는 경고로 남기고 자동 삭제하지 않는다. 전체 목록·보상 입력·허용 행동 후보는 별개 필드로 표현한다.

이 비용은 정차 지점 사이의 도로 최단거리다. 실제 인접 정류장 간선이 아니며 중간에 지나가는 정류장에 자동으로 정차하거나 수요를 얻지 않는다. 같은 정류장에 다시 정차하지 않는 규칙은 이미 지난 도로 재통과 금지와 다르다. 실제 버스의 회전·유턴·사유도로·단지 내부 접근은 미검증이다.

## 6. 보상과 출발·종점 규칙

인계 기본안은 자유 종점이다. 현 코드와 비교할 때 별도의 고정 종점을 새로 가정하지 않으면서 수요·거점·거리 정의를 분리하려는 선택이며, 외부 팀의 동의를 얻었다는 뜻은 아니다. 노선 길이 예산과 출발점은 외부 담당자가 인계 설정에 명시해야 한다.

```text
r(i→j | H) = 1.0*d_j + 0.5*I(hub(j)≠null and hub(j)∉H)
             - 0.2*road_m(i,j)/1000
H_next = H ∪ {hub(j)}  # null 제외
```

- 최초 출발 시 수요 점수·거점 보너스는 지급하지 않는다.
- 출발점의 그룹이 있으면 처음부터 H에 넣는다. 같은 그룹의 다른 정류장에 가도 신규 거점 보너스는 없다.
- 이후 새로 정차하는 모든 정류장의 수요를 포함하며 자유 종점인 마지막 정류장도 포함한다.
- 서로 다른 정류장이라도 같은 거점 그룹의 보너스는 최초 한 번만 지급한다.
- 같은 정류장 ID의 재정차는 허용하지 않는 인계안이다.
- 목표 정류장의 수요 또는 해당 방향 거리가 `null`이면 보상은 정의되지 않는다. 0 보상·0 거리·이동 불가로 자동 해석하지 않는다. 관련 자료를 확보하거나 명시적인 관측 부분집합을 사용해야 한다.

### 계수의 크기와 예시

신규 거점 +0.5는 전역 최대 점수의 절반이며, 1km 비용은 0.2다. 그러나 실제 비중앙차로·수요 관측 집합의 중앙값 점수는 약 0.015588이므로 보너스는 약 32개 중앙값 정류장 또는 2.5km 비용에 해당한다. 따라서 이 값을 수요 중심 균형이라고 설명할 근거는 부족하다. v1 값을 미보정 정책 기준안으로 보존하고 가중치의 교환비율·원시 항을 함께 보고한다. +2도 과거 설정일 뿐 최적성 근거는 없으며, 이번 범위에서 성능 우열을 비교하지 않는다.

다음은 설명용 `d_j=0.4`, 거리 500m 예시다. 실제 최적 노선 결과가 아니다.

| 경우 | 수요 항 | 거점 항 | 거리 항 | 보상 |
| --- | --- | --- | --- | --- |
| 일반 정류장에 새 정차 | 0.4 | 0 | -0.1 | 0.3 |
| 새 거점 그룹에 최초 정차 | 0.4 | 0.5 | -0.1 | 0.8 |
| 이미 보상한 거점 그룹의 다른 정류장 | 0.4 | 0 | -0.1 | 0.3 |
| 출발점 초기화 | 0 | 0 | 0 | 0; 출발 그룹은 H에 등록 |
| 자유 종점으로 마지막 정차 | 0.4 | 신규 그룹이면 0.5 | -0.1 | 0.8 또는 0.3 |
| 수요 또는 거리 미확보 | 정의 불가 | 가산하지 않음 | 정의 불가 | `null`/명시적 오류 |

### 고정 종점 대안

외부 모델 담당자가 고정 종점 g를 채택하면 시작·종료 ID와 예산을 별도 버전 설정으로 기록한다. 완전한 비용 행렬에서 미방문 종점 직행을 항상 허용하고 `사용 거리 + d(i,j) + d(j,g) <= 예산`으로 제한하면 다음 상태에도 종점 직행이 가능하다. 거리 또는 연결이 미확보면 이 판정을 할 수 없다. 제한된 간선·도로 재통과 금지까지 추가하면 그 조건을 반영한 도달성 검사가 필요하다.

이 인계안은 고정 종점에서도 최종 정차의 수요를 포함하는 기본 보상 정의를 유지한다. 같은 출발·종점끼리 비교할 때 종점 수요가 공통 상수임을 표시한다. 외부 팀이 종점 점수를 0으로 정하면 `final_stop_demand_reward=false`로 별도 기록하고 평가표의 포함 범위도 바꿔야 한다. 원문 노션의 종점 제외 규칙을 현재 기본안과 혼동하지 않는다.

## 8. 기존 모델 담당자에게 필요한 적응 사항

기존 `network.json`과 `train.py`는 이번 명세에 맞게 변경하지 않는다. 특히 `Route.__init__`는 원천 월별 하차량에서 월별 일평균의 단순평균을 다시 계산하므로 새 `demand_daily_train`을 읽지 않는다. 원천 월별 배열만 교체한다고 기간 일평균·전역 고정 분모·거점 규칙이 적용되는 것이 아니다.

모델 담당자는 새 버전의 명시적 `demand_score_train`과 `hub_id`, 품질·정차 가정·결측 규칙을 소비하도록 별도로 연결해야 한다. 기존 소비자는 `hub`의 빈 문자열을 쓰지만 새 명세는 `hub_id=null`이므로 필드와 null 변환도 필요하다. 이 연결 코드는 우리 범위에서 구현하지 않는다.

전체 464개 행렬의 null을 numeric-only 모델에 그대로 넣으면 안 된다. 공식 전체 목록과 수요 참조는 인계할 수 있으나 전체 지역의 학습·노선 탐색 입력 준비는 완료되지 않았다. 관측 292개 또는 진단용 259개 부분집합을 사용하더라도 전체 지역 확장 완료라고 보고하지 않는다. 모델 담당자가 해야 할 추가 거리 확보·고정 종점 여부·운행 제약 검증을 한계로 전달한다.
