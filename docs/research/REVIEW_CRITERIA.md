# C 검토 기준: 정류장 맵·수요·거점·보상 인계

작성일: 2026-11-15 (Asia/Seoul)<br>
적용 범위: [오케스트레이션](../../ORCHESTRATION.md)의 4번 역할. 학부 연구 수준의 근거·정의·재현성·한계 설명을 평가하며 모델 구현·학습·성능 비교는 요구하지 않는다.

이 문서는 검토 기준이다. 작성 중인 문헌·공간 감사나 향후 명세가 통과했다는 판정은 아니다. 현재 점검 리포트와 기존 데이터 감사는 검토 출발점이며, 과거 코드 기본값을 연구적으로 최적인 선택으로 간주하지 않는다.

## 1. 판정 원칙

| 판정 | 의미 | 후속 처리 |
| --- | --- | --- |
| 통과 | 해당 단계의 필수 기준을 충족하고 주장 범위가 근거와 일치 | 다음 단계 진행 |
| 수정 후 재검토 | 계산·정의·인용·데이터 연결 등 고칠 수 있는 문제가 있음 | 문제 위치와 완료 조건을 명시해 수정 |
| 근거·자료 부족 | 핵심 주장을 뒷받침할 원문 또는 자료가 없음 | 무료 대안·보수적 가정·주장 축소 검토 |

자료 부재를 숨겨 통과시키지 않는다. 다만 일부 지역 완전성·현실 운행 가능성을 입증하지 못해도 그 한계를 명확히 표시한 연구용 부분 산출물의 제작은 진행할 수 있다. 이 경우 부분 산출물의 통과와 ‘서대문구 전체 정류장 완성’ 주장의 통과를 분리한다.

동일 쟁점의 두 차례 수정에도 해결되지 않으면 실제 가능한 범위와 남는 한계를 명시한다. 사용자에게 선택이나 비용 승인을 요청하는 방식으로 검토를 종료하지 않는다.

## 2. 1단계 조사 결과 검토

### 2.1. 선행연구

필수 기준:

1. 단일 논문의 방법을 그대로 복제하는 대신 서로 다른 관점의 복수 자료를 검토한다. 노선·정류장 선택, 예산 제약 경로, 접근성·환승 거점 등 이번 설계와 직접 연결되는 근거를 확보한다.
2. 제목·저자·연도·원문 URL, 실제 확인한 절·페이지 또는 읽은 범위를 기록한다. 초록만 읽은 자료와 본문을 확인한 자료를 구별한다.
3. 핵심 설계의 근거는 연구 원문 또는 공식 자료에서 확인한다. 검색 결과 문구, 2차 블로그, 생성된 요약을 원문의 주장으로 인용하지 않는다.
4. `문제 → 근거 → 대안 → 채택 이유 → 한계` 연결이 있다. 논문의 연구 도시·데이터·목적함수와 우리 조건의 차이를 설명한다.
5. ‘논문이 입증한 사실’, ‘현재 자료의 사실’, ‘우리 프로젝트 가정’을 분리한다.
6. 수요 대리 지표, 거점 보상, 방향별 거리, 정규화에 대해 참고할 근거가 있는지 확인한다. 논문에서 특정 정규화나 반경을 지지하지 않으면 자체 선택이라고 명시한다.

반려할 예:

- OD 기반 수요를 최적화한 논문의 성과를 근거로 정류장별 하차량 합이 신규 노선 수요를 예측한다고 주장한다.
- 다른 도시의 보행 반경이나 보상 계수를 서울에 적용하면서 최적값 또는 검증값이라고 부른다.
- 원문에 없는 수치나 결론을 논문에서 도출했다고 기록한다.

### 2.2. 데이터·공간 감사

필수 기준:

1. `연구 지역 808개`, `그중 112 접두어 282개`, `행정구역 전체 정류장`의 세 모집단을 구별한다.
2. 전체 목록을 확보했다면 원천·시점·ID 체계와 공간 필터를 기록하고 원본 분석 자료와 차집합을 산출한다. 공식 목록과의 단순 개수 비교만으로 완전성을 주장하지 않는다.
3. 전체 목록을 확보하지 못했으면 확보 경로의 한계와 필요한 변수·자료를 적고 `coverage_complete=false`에 준하는 명시적 상태를 유지한다. 기존 연구 경계만으로 행정구역 전체라고 이름 붙이지 않는다.
4. 정류장·월별 하차량·거리 행과 열·스냅 정보의 ID 연결을 확인한다. 실제 0명, 원천 행 없음, 거리 없음, 사용 제외를 구별한다.
5. 07시대·08시대 합, 월간 합계와 일평균, 달력 일수와 평일 추정, 학습·검증 기간을 구별한다.
6. 중앙차로 정류장 제외 표시는 연구 가정임을 설명한다. 단순히 ‘법적 정차 불가’로 승격하지 않는다.
7. 거리의 방향·단위·대각선·비대각 0m·결측·스냅 품질을 확인한다. 원본 값을 보존하고 대체값은 별도 필드로 구별한다.
8. 거점 기준점 좌표는 위치 원천과 함께 제시한다. 공식 역 좌표가 출입구 좌표와 같지 않다는 점을 표시하고, 이름만으로 자동 매핑하지 않는다.

실행 가능한 범위 조정:

- 새로운 정류장의 좌표만 확보되고 수요·도로거리가 없으면 참조 지도 레이어에 표시할 수 있지만 분석 후보로 완전 결합된 것처럼 취급하지 않는다.
- 다른 시점의 공식 목록은 현재 자료의 포괄성 참고가 될 수 있다. 정류장 신설·폐지·ID 변경을 고려하지 않은 차집합을 곧바로 수집 누락으로 확정하지 않는다.
- 282개 전체와 중앙차로 제외 259개 중 기본 집합을 정할 때, 제외 이유를 기록하고 원본 전체를 참조용으로 보존한다. 두 집합의 수요 정규화 기준이 달라졌다면 같은 척도로 비교했다고 표현하지 않는다.

### 2.3. 조사 단계 통과 조건

B와 D의 조사 결과가 서로 모순되지 않고, E가 설계할 수 있는 데이터 범위·단위·품질·문헌 근거가 확보되면 통과한다. 행정구역 완전성 미해결은 제한을 명시한 부분 설계 진행을 막는 이유가 되지는 않지만, ‘전체 확장 완료’ 주장은 계속 보류한다.

## 3. 3단계 설계 명세 검토

### 3.1. 수요와 정규화

- 기본 수요는 보유 자료에서 재계산 가능한 식으로 정의한다. 기간 일평균을 목표로 한다면 `학습 월 하차량 총합 / 학습 월 달력 일수 총합`이 자연스러운 출발점이며, 이는 목표 평균의 정의에 따른 선택이다. 선행연구가 보장한 최적 산식이라고 주장하지 않는다.
- 월별 일평균의 단순평균을 채택하려면 월별 동일 가중의 의미를 설명한다. 기존 코드와 정의가 바뀌면 산출물에 그 차이를 표시한다.
- 정규화는 한 가지 기본안을 선택하고 식·모집단·최솟값/최댓값·동일값 예외·클리핑 여부를 명시한다. 최대값 나눗셈과 min-max 중 어떤 안도 근거 없이 자동 정답으로 두지 않는다.
- 5–8월에서 정한 척도를 9–10월에도 고정한다. 월마다 정규화해 높고 낮음의 의미가 바뀌는 방식은 별도 시각화로만 분리하고 공통 보상 입력과 혼동하지 않는다.
- 검증값이 학습 범위를 벗어날 때 허용·클리핑 중 정책을 정한다. 지도 표시 범위와 실제 보상값을 구별한다.
- 정의 차이의 중요성과 실제 수치 영향의 크기를 구별한다. 현재 [정의 비교](../evidence/demand_definition_audit.json)에서는 282개 기준 최대값/최소-최대 정규화의 최대 차이가 약 `2.88×10^-5`이고 평균 방식별 상위 10개도 같다. 따라서 정의를 통일할 필요는 있지만 노선 결과가 크게 달라질 것이라고 단정할 근거는 없다. 후보 집합이 달라지면 그 집합에서 다시 확인한다.
- 하차량을 신규 탑승객, 고유 승객, 추가 수요, OD로 표현하지 않는다. 경유 정류장 합계는 기존 하차 실적의 커버리지 대리 지표라고 명시한다.

### 3.2. 거점과 접근성

- 거점 ID는 실제 역 또는 연대앞 접근 지점의 의미를 가져야 한다. 환승역의 노선별 중복 레코드와 같은 이름의 서로 다른 역을 구별한다.
- 기준점 원천·좌표 체계·거리 계산법·반경·단일/복수 귀속·동률 규칙을 명시한다.
- 보행 경로 자료가 없으면 직선 거리를 사용한 근사임을 표시한다. 도로 장벽·출입구·횡단 조건을 검증했다고 주장하지 않는다.
- 기본 반경은 근거를 가진 실무 가정으로 정할 수 있으나 ‘서울에서 최적’이라고 부르지 않는다. 다른 반경에서 매핑 수·중첩·미연결 거점이 얼마나 달라지는지 확인하는 것은 공간 데이터 검증이며 모델 성능 실험이 아니다.
- 보너스는 거점 그룹별 최초 한 번이라는 기본 규칙과 출발 시 이미 방문 처리·종점 포함 여부를 명시한다.
- 한 정류장의 복수 거점 보너스를 허용한다면 중첩 보상 이유를 설명한다. 보수적 기본안으로 단일 최근접 귀속을 택할 수 있으며 이때 잃는 다중 접근성을 한계로 적는다.

### 3.3. 거리·정차·보상

- 방향별 모든 쌍 최단거리 행렬은 정차 지점 사이 이동 비용이다. 이를 실제 인접 정류장 간선이나 버스 운행 적합성 인증으로 설명하지 않는다.
- 재정차 금지와 이미 지난 도로의 재통과 금지를 구별한다.
- 스냅상 비대각 0m가 있다면 값 보존·품질 경고·후속 처리 규칙을 정한다. 임의의 1m 대체로 현실 거리를 수정했다고 주장하지 않는다. 효율식의 분모 보호값과 보상 거리 자체의 수정은 별개다.
- 보상식의 수요 항·거점 항·거리 항을 분리하고 단위를 명시한다. 적어도 일반 정류장, 신규 거점, 이미 보상한 거점, 출발·종점의 수치 예시로 정의를 확인한다.
- 수요 점수의 상한과 거점·거리 계수의 상대적 크기를 설명한다. 계수는 인계용 연구 가정이며 현재 범위에서 최적화하지 않는다.
- 출발·종점 규칙은 우리 기본 인계안과 외부 모델 팀의 실제 합의를 구별한다. 우리 명세를 타 팀이 채택했다고 표현하지 않는다.
- 원본·가공 입력과 품질 플래그·매핑 근거를 함께 보존한다. 기존 모델 입력에 없는 필드를 추가하면 호환성 또는 변환 절차를 문서화한다.

### 3.4. 설계 단계 통과 조건

명세만 읽어 D와 F가 같은 정류장 집합·수요값·거점·거리·보상 예시를 재현할 수 있어야 한다. 핵심 선택마다 문헌 근거·자료 기반 이유 또는 명시적 연구 가정이 있어야 한다. 모델 학습 결과는 통과 증거로 요구하지 않는다.

## 4. 6단계 최종 산출물 검토

| 확인 항목 | 최소 완료 증거 |
| --- | --- |
| 분석 범위 | 포함·제외 ID와 이유, 완전성 상태, 참조 목록과 분석 후보의 구별 |
| 데이터 일치 | 정류장·수요·거리의 ID 순서 일치 및 누락 처리 보고 |
| 수요 추적 | 정류장 하나 이상의 월별 원본 → 학습 일평균 → 정규화 → 지도/입력 값 일치 |
| 거점 추적 | 기준점 출처, 반경·계산법, 정류장 매핑 근거, 중첩·미연결 목록 |
| 거리 품질 | 방향·단위, 0m 경고, check/unverified 식별, 원본값 보존 |
| 보상 정의 | 항별 산식·단위·예시·그룹 최초 지급·출발/종점 규칙 |
| 지도 | 실제 좌표, 수요·거점·품질 범례, 필요한 정류장 정보, 데이터 범위·근사 한계 표시 |
| 지도 의미 | 직선 표시를 도로 경로로 부르지 않음; 실제 주행 가능성 미검증 표시 |
| 인계 | 변수 사전, 스키마·버전·정류장 순서, 재생성 명령, 외부 담당자가 결정/검증할 항목 |
| 검증 | 전처리 재실행, 핵심 데이터 불변조건과 독립 산술 확인, 링크/파일 및 지도 기능 확인 |
| 연구 기록 | 문헌·방법·결과·반론·선택 이유·남는 한계가 연구일지에서 추적 가능 |
| 범위 준수 | 새 비용·모델 구현·모델 학습·성능 비교 실험 없이 완료 |

검증은 데이터 불변조건과 계산 의미를 확인해야 한다. 단순히 함수가 작성한 값을 같은 함수로 다시 읽는 자기 확인만으로 독립 검증을 대체하지 않는다. 반대로 저위험 문구 변경마다 불필요한 테스트를 추가할 필요는 없다.

## 5. 현재 자료로부터의 보수적 권고

다음은 B·D 조사와 실제 명세를 검토하기 전의 권고이며 확정 설계 판정이 아니다.

1. 행정구역 전체를 입증하지 못하면 지도 제목과 인계 metadata에서 ‘보유 연구 지역의 서대문구 정류장’으로 범위를 제한한다. 북부 등이 빠졌다는 지리적 의심도 외부 목록·경계와 대조하기 전에는 구체적 누락 개수로 표현하지 않는다.
2. 원본 282개를 보존한 참조 레이어와 정차 가정에 따른 분석 후보 레이어를 분리하면 범위 축소와 품질 필터를 설명하기 쉽다. 제외한 중앙차로를 지도에서 완전히 숨기지는 않는 편이 좋다.
3. 하차량 기반 기간 일평균, 학습에서 고정한 정규화, 그룹당 한 번 보너스는 재현 가능한 인계안의 출발점이 될 수 있다. 각각의 실제 선택 이유와 대안을 문헌 검토 및 명세에서 설명한다.
4. 거점 반경은 현재 자료에서 지원하는 공간적 근사로 취급한다. 공개 역 좌표를 쓰더라도 실제 출입구·도보 접근성을 입증한 것은 아니다.
5. 기존 `network.json`과 다른 수요·후보·거점 정의가 필요하면 새 버전의 인계 산출물로 제공하고 차이를 설명한다. 모델 코드까지 우리 범위에서 수정하지 않는다.
6. 완성 판정은 신뢰할 수 있는 지도와 데이터·설계 인계의 완료를 뜻한다. 최적 노선, 실제 수요 예측, 신규 서비스의 운행 승인 또는 알고리즘 성능 입증을 뜻하지 않는다.

## 6. C 중간 판단: 새 전체 정류장 도로거리 자료 생성

현재 검토 중인 확장안은 공식 정류장 참조 집합 464개에 대해 별도의 OSM 차량 도로망에서 방향별 최단거리를 재생성하는 것이다. 정확한 모집단 수와 일치·누락 개수는 D의 최종 감사로 확인해야 하며, 이 절은 해당 숫자를 독립 확정한 결과가 아니다.

**판단:** 무료 공개 도로망과 로컬 최단거리 계산으로 새로운 연구용 거리 자료를 만드는 것은 4번 역할의 데이터 전처리 범위에 들어간다. 구현·자료 검증 기준을 충족하면 학부 연구의 근사 이동 비용으로 사용할 수 있다. Dijkstra를 통한 도로 최단거리 산출은 학습 모델 구현이나 노선 선택 성능 실험이 아니다. 다만 이는 실제 마을버스 운행 적합성·법적 회전 가능성의 검증을 뜻하지 않는다.

### 6.1. 표현해야 할 방법론적 근거

OSMnx의 공식 문서는 차량 도로망을 방향 그래프로 구성하고, 연결 성분 보존 여부와 경계에서의 그래프 절단을 별도 설정으로 다룬다. 이는 도로 그래프 범위와 단절 처리가 결과에 영향을 주는 명시적 설계라는 근거다. OSMnx를 실제로 사용하지 않고 직접 구현한다면 OSMnx 사용 결과라고 표현하지 않는다. [OSMnx 공식 그래프 문서](https://osmnx.readthedocs.io/en/stable/user-reference.html)

OSM의 방향 규칙에는 `oneway=yes`, `oneway=-1`과 회전교차로 등의 암시적 일방통행이 있다. `access`·차종별 접근 태그와 회전 제한 관계는 방향 태그만으로 대체되지 않는다. [OSM 방향 태그](https://wiki.openstreetmap.org/wiki/Key:oneway), [OSM 라우팅 태그](https://wiki.openstreetmap.org/wiki/OSM_tags_for_routing), [OSM 회전 제한 관계](https://wiki.openstreetmap.org/wiki/Relation:restriction)

### 6.2. 제작을 진행할 조건

- 자료 조회는 공개·무료 범위에서 제한된 횟수와 시간으로 시도한다. 접근 실패 시 유료 서비스나 사용자 요청으로 전환하지 않고 부분 산출물로 전환한다.
- 쿼리·도로 스냅샷 날짜·원본 응답·다운로드 원천·사용 태그·재생성 코드를 남긴다. OSM 출처·저작권·ODbL 정보를 인계한다.
- 새 그래프에서 모든 정류장 거리를 일괄 생성한다. 기존 연구 지역의 거리와 새 거리의 서로 다른 산출 방법을 한 행렬 안에서 섞지 않는다.
- 정류장 외곽에 여유 경계를 두고 도로 밖 우회 경로가 잘려 짧은 실제 경로를 놓칠 수 있음을 검토한다. 경계 영향이 남으면 한계로 적는다.
- 도로 분류·일반 접근·차량 접근 태그 필터를 선언하고, 보행로·계단 등을 차량 간선으로 넣지 않는다. 사유지·시간 조건·버스 예외 등을 완전 처리하지 못한 부분은 명시한다.
- OSM의 도로 중간 노드와 실제 형상 길이를 보존한다. 선분을 단순 두 끝점 직선으로 축약하여 곡선 도로 길이를 과소계산하지 않는다.
- 일방통행의 순방향·역방향과 암시적 회전교차로 방향을 처리한다. 회전 제한 관계를 구현하지 않으면 회전·유턴 검증 미완료로 표시한다.
- 정류장 스냅은 미터 단위 투영 또는 명시적 지리 거리로 계산한다. 위·경도 도 단위 거리를 m로 취급하지 않는다.
- 정류장 투영점의 간선 내 오프셋을 처리하고, 같은 방향 간선 위 두 정류장의 직접 부분구간 이동을 허용한다. 모든 이동을 간선 끝점까지 갔다가 되돌아오는 방식으로 만들지 않는다.
- 정류장과 투영점 사이 연결 비용을 포함하는지, 어떤 방향으로 포함하는지 정의한다. 이러한 직선 연결은 실제 진입·정차 동작의 검증이 아니라 위치 근사다.
- 오른쪽 도로면 판별은 스냅 품질 휴리스틱이다. 이 판별만으로 올바른 차로·출입구·정차 방향이 검증되었다고 하지 않는다. 반대편 또는 멀리 있는 도로를 선택하는 이상 사례를 별도 확인한다.

### 6.3. 최종 거리 자료의 검토 기준

| 검사 | 요구되는 결과 또는 정직한 처리 |
| --- | --- |
| 모집단·순서 | 공식 기준 집합·수요·행렬 행/열이 동일 ID와 순서를 사용 |
| 방향·단위 | 명시적 방향 그래프와 m 단위, 음수·비유한 수치 없음 |
| 기하 | 스냅거리·방향·도로 분류·품질 플래그를 정류장별 보존 |
| 연결성 | 도로 연결 성분과 도달 불가 정류장·쌍 수를 보고 |
| 도달 불가 | `null` 등 스키마에 정의된 결측으로 유지; 직선거리로 도로거리를 가짜 보완하거나 정류장을 조용히 제거하지 않음 |
| 대각선·0m | 대각선은 0, 비대각 0m는 같은 투영점 여부와 원인 검토 |
| 산술 검증 | 작은 예제에서 순방향·역방향·같은 간선·분리 성분의 기대 거리를 독립 계산해 확인 |
| 공간 검증 | 큰 스냅거리, 과도한 우회, 도로거리보다 긴 직선거리 등 이상 구간을 찾아 원인 확인 |
| 기존 자료 비교 | 겹치는 정류장 일부의 거리 차이·비율을 품질 진단으로 확인; 시점·스냅 방법 차이를 고려해 불일치 자체를 오류로 확정하지 않음 |
| 재현성 | 같은 원본 스냅샷과 설정에서 같은 정류장 순서·행렬·메타데이터 생성 |

스냅 경고 기준이나 표본 개수는 엔지니어링 검토 규칙으로 표시하며 학술적으로 최적인 임계값이라고 부르지 않는다. 표본 검사로 전체 실제 주행을 검증했다고 표현하지 않는다.

모든 요구 정류장의 수요와 유한한 방향별 거리가 있더라도 그것만으로 충분하지는 않다. 계산·방향·단위·스냅 검증을 통과해야 연구 입력의 준비 상태를 올릴 수 있다. `데이터 결합 완료`, `연구용 근사 거리 준비`, `실제 버스 운행 검증`은 다른 상태로 관리하고 마지막 상태는 미검증으로 유지한다.

### 6.4. 무료 도로자료 확보 또는 검증 실패 시

전체 정류장 참조 지도와 확보한 수요를 제공하되, 거리 결합 가능한 부분 행렬만 분리해 인계한다. 전체 집합의 거리 준비 상태는 미완료로 표시한다. 이는 유효한 부분 산출물이며, 전체 정류장 확장의 거리 입력까지 완료했다는 주장은 허용하지 않는다.
