# 연구일지

이 일지는 연구 질문·근거·방법·결과·설계 판단과 한계를 기록한다. 에이전트 운영이나 파일 수집 과정은 기록하지 않는다. 아래 초기 항목은 이미 수행한 데이터 분석 결과를 근거 파일에 연결한 것이며, 새 문헌 연구나 독립 평가를 수행했다고 주장하지 않는다.

## R001 / 2026-11-15 / 분석 정류장 모집단의 완전성

**질문과 문제의식:** 현재 모델의 282개 정류장을 ‘서대문구 전체’로 해석할 수 있는가? 작은 후보 집합의 한계를 개선하려면 후보 수와 모집단의 완전성을 구분해야 한다.

**근거:** 전처리 정류장 CSV 808행, 현재 모델 입력, 데이터 설명 원문. [원본 자료](../notion/01_data_preprocessing.md), [분석 결과](../evidence/source_data_audit_2026-11-15.json).

**방법:** `station_id`를 문자열로 읽어 접두어별 개수를 집계하고, 원본 중 `112` 접두어 ID 집합과 현재 입력 ID 집합의 차집합을 비교했다.

**결과:** 원본의 `112` 접두어는 282개이며 현재 입력과 정확히 일치한다. 전체 원본은 여러 접두어의 정류장 808개로 구성된다. 원문은 연구 범위에서 6개월 승하차 기록이 없는 12개를 제외했다고 설명한다.

**해석:** 현 입력은 ‘보유 연구 지역 자료의 112 접두어 전체’다. 이 결과는 행정구역 전체 수집을 입증하지 않으며, 808개를 그대로 쓰는 것 역시 서대문구 전체와 동의어가 아니다.

**한계·다음 질문:** 원래 연구 경계, 제외된 12개의 위치·ID, 행정구역 전체 목록과의 차이를 확인해야 한다. 전체 수집 여부가 검증되기 전에는 포괄성을 단정하지 않는다.

## R002 / 2026-11-15 / 오전 하차 수요의 산식 일관성

**질문과 문제의식:** 지도 점수와 모델 입력이 같은 수요를 표현하는가? 월평균·기간평균·평일 추정치를 혼용하면 보상 해석이 달라진다.

**근거:** 월별 수요 CSV 4,848행, 현재 `train.py`의 수요 산식, [방법론 문서 §2.2](../notion/02_jua_role3.md), [데이터 분석](../evidence/source_data_audit_2026-11-15.json).

**방법:** 모든 행에서 `alight_07_09`와 `alight_07 + alight_08`을 비교하고, 시간·일수·분할 열 및 코드·문서의 산식 정의를 대조했다.

**결과:** 시간대 합산 불일치 0건, `has_source_record != 1`인 행 0건이다. 코드의 학습 수요는 5–8월 월별 하차량/달력 일수의 단순평균이고 정규화는 최댓값 나눗셈이다. 방법론 문서는 기간 총하차량/총일수 및 min-max 정규화를 제시한다. `weekday_avg_07_09_est`는 승하차 합계의 평일 추정치다.

**해석:** 코드·방법론 사이의 수요와 정규화 정의가 다르다. 평일 승하차 추정치를 평일 하차량으로 사용하면 안 된다. 하차 실적은 신규 노선 수요의 대리 지표로만 해석해야 한다.

**한계·다음 질문:** 현재는 차이 확인까지 수행했다. 채택 산식은 선행연구와 분석 목적을 검토한 뒤 결정하고 지도·입력·명세에 일관되게 적용해야 한다. 코드 기본값을 연구적 최적값으로 간주하지 않는다.

## R003 / 2026-11-15 / 거점 접근성과 정차 가정의 충돌

**질문과 문제의식:** 연대앞과 지하철역 거점을 확대할 때, 보너스를 받을 정류장이 연구상 정차 제외 후보와 겹치는가?

**근거:** 원본 정류장의 유형·`village_bus_stoppable`, 현재 거점 매핑, [기초 입력 분석](../evidence/network_audit_2026-11-15.json), [원본 대조](../evidence/source_data_audit_2026-11-15.json).

**방법:** 현 입력 282개에 원본의 정류장 유형을 결합하고 정차 가능 표시가 0인 정류장을 추출했다. 기존 거점 그룹과 역 주변 정류장을 대조했다.

**결과:** 현재 거점은 8개 정류장·4개 그룹이다. 현 입력에는 정차 표시 0인 중앙차로 정류장 23개가 포함되어 있으며 서대문역·충정로역·연세대앞 일부도 해당한다. 표시 0은 원문에서 중앙차로를 후보에서 제외한다는 연구 가정이다.

**해석:** 역 이름만으로 거점을 추가하면 정차 가정과 충돌할 수 있다. 역 접근성과 실제 보너스 대상 정류장을 구별해야 하며, 이 표시를 실제 법적 정차 금지의 확정 사실로 표현해서도 안 된다.

**한계·다음 질문:** 거점 접근 반경·출입구·단일 또는 복수 귀속 기준이 아직 연구적으로 확정되지 않았다. 거점 그룹당 보너스 중복 방지와 정차 후보 정책을 함께 설계해야 한다.

## R004 / 2026-11-15 / 방향별 도로거리와 0m 이동의 해석

**질문과 문제의식:** 서로 다른 정류장 사이의 0m 이동은 결합 오류인가, 스냅에 따른 근사인가? 거리 행렬만으로 주행 가능성을 주장할 수 있는가?

**근거:** 282×282 거리 행렬, 원본 거리 ZIP, 정류장 스냅 CSV, [입력 분석](../evidence/network_audit_2026-11-15.json), [원본 대조](../evidence/source_data_audit_2026-11-15.json).

**방법:** 비대각 거리의 음수·비유한값·0m를 검사하고 발견한 0m 정류장 쌍의 스냅 도로 노드·오프셋을 대조했다. 원본에서 현재 입력을 재생성하여 일치 여부도 확인했다.

**결과:** 음수·비유한 거리 0건, 대각선 모두 0이다. `112900003 → 112900157`은 서로 다른 ID·좌표인데 0m다. 출발 정류장은 도로 구간 끝, 도착 정류장은 이어지는 구간 시작에 스냅되어 공통 노드 `2451941009`를 공유한다. 원본으로 재생성한 입력은 기존 입력과 바이트 단위로 같다. 현 정류장의 스냅 품질은 `ok` 261, `check` 17, `unverified` 4개다.

**해석:** 0m는 원본 스냅 근사로 설명되며 단순 데이터 결합 오류로 보이지 않는다. 그러나 실제 정차 위치 사이 이동비용으로 적절한지는 별도 검토가 필요하다. 현 행렬은 방향별 OSM 차량 도로망 최단거리이며, 실제 버스 회전·유턴·단지 내부 통행 가능성까지 증명하지 않는다.

**한계·다음 질문:** 실제 정차 위치의 거리 처리 기준과 품질 플래그 사용 원칙을 정해야 한다. 거리 생성 전 과정을 재현하거나 실제 주행을 검증한 결과는 아니다.

## R005 / 2026-11-15 / 보상 크기와 이동 규칙의 초기 진단

**질문과 문제의식:** 현재 보상이 수요·거점·거리 사이에 어떤 상대적 우선순위를 부여하는가? 발표와 코드가 같은 경로 선택 문제를 설명하는가?

**근거:** `train.py`의 `Route.actions`, `Route.gain`, `Route.step` 및 기본 인수, 발표·방법론 대조를 정리한 [점검 리포트](../ROLE4_REVIEW_AND_PLAN.md).

**방법:** 보상 항별 범위·단위를 대수적으로 비교하고 상태·종료·허용 행동의 코드 정의를 문서와 대조했다. 모델 학습이나 성능 비교로 판단한 것은 아니다.

**결과:** 현 보상은 정규화 수요 최대 1, 신규 거점 +2, 거리 -0.2/km다. 6km 이동 패널티는 최대 1.2다. 현 코드는 예산 안의 모든 미방문 정류장을 허용하고 지정 종점을 두지 않는다. 발표에는 인접 간선과 지정 종점이 제시된다.

**해석:** 현 가중치는 거점 방문에 비교적 큰 점수를 부여할 수 있다. 그 자체로 부적절함을 입증하지는 않는다. 완전 거리 행렬에서 정차 지점을 고르는 문제와 인접 그래프 위의 경로 문제를 구분해야 한다.

**한계·다음 질문:** 보상 최적값·알고리즘 우열은 결론 내리지 않는다. 선행연구 근거와 C의 검토로 인계할 설계의 의미를 확정하고, 모델 담당자가 검증할 사항과 우리 데이터·설계 검증을 구별한다.

## R006 / 2026-11-15 / 공식 정류장 코드에 따른 모집단 재정의

**질문과 문제의식:** R001의 282개 목록은 실제로 어느 범위를 놓치며, 내부 ID 접두어를 지역 필터로 써도 되는가?

**근거·방법:** 서울시 OA-15067의 2026-09-02 정류장 목록과 OA-22187의 구별 ARS 코드 정보를 대조했다. ARS 지역 코드 `13=서대문구`로 정류장을 추출하고 내부 NODE ID 접두어·원래 808개 자료·기존 입력의 ID 집합을 비교했다. [공간 감사](DATA_SPATIAL_AUDIT.md), [정량 근거](../evidence/spatial_audit.json).

**결과:** 공식 ARS 13 목록은 464개이며 내부 NODE ID가 112로 시작하는 정류장은 449개다. 다른 NODE 접두어를 가진 15개도 ARS 13에 속한다. 기존 입력은 282개로 464개의 약 60.78%이며, 원래 808개 자료와 겹치는 정류장은 292개다. 원본 도로 자료는 이 292개 사이 방향별 84,972쌍을 제공하나 전체 464개에 필요한 214,832쌍 중 129,860쌍은 없다.

**해석·선택 이유:** 지도 모집단은 내부 ID 112가 아닌 공식 ARS 13의 464개로 확장한다. 기존 282개만을 서대문구 전체라고 부르는 해석은 수정한다. 지도 모집단과 모든 수요·거리가 확보된 집합을 구별한다.

**한계:** 이 정의는 공식 코드 기반이며 행정구역 폴리곤의 지리적 포함 판정은 아니다. 정류장 목록과 수요의 시점 차이·개폐 이력은 남은 불확실성이다. 거리 미확보를 임의 직선거리나 0으로 채우지 않는다.

## R007 / 2026-11-15 / 전체 기준 목록의 월별 하차량 재집계

**질문과 문제의식:** 기존 연구 지역 밖 정류장의 수요를 공식 월별 자료에서 재구성할 수 있는가? 관측 부재와 0명을 어떻게 구별하는가?

**근거·방법:** 서울시 [OA-12913](https://data.seoul.go.kr/dataList/OA-12913/S/1/datasetView.do)의 2026년 5–10월 버스노선·정류장별 시간대별 원자료를 사용했다. 월별 노선·방향 행을 표준 정류장 ID로 합산하고 07시대와 08시대 하차량을 더했다. 공식 ARS 13의 464개에 왼쪽 결합했으며 행 부재는 빈 수치와 `has_source_record=0`으로 표시했다. [원자료·집계 근거](../../data/reference/ridership_provenance.json), [재현 코드](../../scripts/fetch_role4_ridership.py).

**결과:** 매월 동일한 454개에 원천 기록이 있고 10개에는 없다. 기존 팀의 지역 집계와 비교 가능한 서대문구 정류장의 월별 하차량은 모두 일치했다. 학습 4개월은 총 123일이다. 454개 중 학습 일평균 실제 0인 정류장은 1개이며, 기록 없는 10개와 구별된다. 전체 454개 기준 최댓값은 서대문역 `112000403`의 약 847.789명/일이다.

**해석:** 전체 기준 목록의 대부분에 수요를 확장할 수 있다. 하차량이 없는 정류장이라는 표현 대신 ‘원천 기록을 확인하지 못한 정류장’으로 표시한다. 전체 학습 모집단의 최솟값이 0이므로 이 모집단에서는 max-only와 min-max가 수치적으로 같다. R002·R005의 기존 282개 산식 차이를 확대된 모집단에서도 큰 효과로 일반화하지 않는다.

**한계:** 기록 부재의 원인이 정류장 개폐·이름 또는 ID 변경·실제 미이용 중 무엇인지는 확정하지 못했다. 월간 집계만으로 평일 하차량이나 신규 노선 수요를 추정하지 않는다. 확장 수요가 있어도 도로거리 미확보가 자동으로 해결되는 것은 아니다.

## R008 / 2026-11-15 / 선행연구로부터 가능한 문제 정의의 경계

**질문과 문제의식:** 하차 실적·거점·도로거리만 있는 상황에서 무엇을 연구 목적과 보상으로 정당화할 수 있는가?

**근거·실제 검토 범위:** [문헌 분석](LITERATURE_REVIEW.md)에 기록한 Tsiligirides(1984)의 가치 수집 경로, Holliday 등(2025)과 Poudel 등(2026)의 OD 기반 교통망 설계, Daniels·Mulley(2013)의 보행 접근 연구, TfL(2015)의 접근성 지침의 관련 절을 검토했다. 원문 링크와 읽은 범위는 [서지 기록](literature_sources.json)에 있다. 모든 논문의 전체 수식·실험을 재현한 것은 아니다.

**결과·해석:** 거리 예산 안에서 가치 있는 정차 지점을 고르는 구조는 설명할 수 있다. 반면 OD·배차·용량·환승시간이 없으므로 하차량 합과 역 근접 보너스를 실제 승객 통행 편익으로 해석할 수 없다. 문헌의 접근 반경은 지역·교통수단·측정 방법에 의존하며, 서울의 특정 직선 반경이나 보너스 계수의 최적성을 입증하지 않는다.

**설계 근거:** 기간 일평균은 모든 관측 날짜를 같은 비중으로 다루는 통계적 정의이고, max-only 정규화는 양수 비율과 영점을 보존하는 프로젝트 선택이다. 거점 그룹당 최초 한 번 보너스는 같은 접근 목적지의 중복 가산을 줄이려는 선택이다. 문헌이 이 수식·계수의 최적값을 처방했다고 주장하지 않는다.

**한계·다음 질문:** 역 기준점과 버스정류장의 직선거리를 실제 도보 환승거리로 해석하지 않는 매핑 규칙이 필요하다. 보상 계수는 명시적인 정책 선호로 제공하고 최적 노선·알고리즘 성능 검증은 우리 결론에서 제외한다.

## R009 / 2026-11-15 / 수요·거점·보상의 기본 인계안 선택

**질문:** 원자료와 문헌의 한계를 유지하면서 다른 담당자가 재현할 수 있는 기본 정의는 무엇인가?

**근거·방법:** R006–R008의 모집단·수요·문헌 결과를 종합하고, 전역 수요 척도와 거점 반경별 단일 귀속을 계산했다. 정류장 점수·거리비용·중복 그룹 보너스를 작은 수치 예제로 분해했다. [명세](DATA_REWARD_SPEC.md), [설정](../../data/role4_config.json), [공간 매핑 결과](../../data/processed/hub_sensitivity.json).

**선택과 이유:** 공식 464개를 보존하고 완전 학습 기록 454개 전체의 기간 일평균 최댓값으로 정규화한다. 중앙차로·거리 가용성 필터마다 분모를 바꾸지 않아 점수의 의미를 유지한다. 기준점까지 구면 직선거리 300m 안의 최근접 그룹 하나만 배정하고, 이미 방문한 그룹의 보너스는 반복 지급하지 않는다. 기본 수요 가중치 1, 신규 그룹 +0.5, 1km -0.2는 수요와 거점 선호를 구별하기 위한 명시적 정책값이다. 서울의 최적값으로 주장하지 않는다.

**결과:** 200/300/500m에서 배정 정류장은 61/103/186개이며, 500m에서는 36개가 복수 그룹 후보를 갖는다. 단일 귀속에서는 후보가 존재해도 더 가까운 다른 그룹으로 배정될 수 있으므로 ‘반경 안 후보 없음’과 ‘최종 배정 없음’을 별개 지표로 보존했다. 수요 점수 0.4, 거리 500m 예시는 일반 정류장 0.3, 신규 그룹 0.8, 이미 방문한 그룹의 다른 정류장 0.3이다.

**연구적 검토와 수정:** 반경·보너스의 자의성을 숨기지 않고 설정 가능한 연구 가정으로 명시했다. 자유 종점 기본안은 새 고정 종점 가정을 피하고 현 코드의 의미와 연결하려는 인계 선택이다. 이를 외부 모델 팀의 합의로 표현하지 않으며, 고정 종점 대안과 종점 수요 포함 규칙도 구별한다.

**한계:** 실제 보행 접근과 거점의 다중 접근성을 충분히 표현하지 못한다. 보상 가중치의 실서비스 편익이나 학습 성능은 검증하지 않았다. 현재 모델은 월별 평균을 재계산하므로 새 점수 입력을 자동으로 사용하지 않는다는 적응 사항을 명시했다.

## R010 / 2026-11-15 / 완전한 참조 지도와 불완전한 이동 입력의 구분

**질문:** 전체 정류장 표현과 모델 입력의 완성을 구분한 부분 인계가 과학적으로 유효한가?

**방법:** 공식 목록·월별 원본·도로 원본·거점 기준점을 공통 ID 순서로 결합했다. 464개×6개월 하차량과 학습 점수를 전수 대조하고, 거리 행렬 원본 보존·CSV 결측·지도 내장 자료와 통합 JSON의 동일성을 확인했다. 원본 재집계와 단위·그룹·결측 의미에 대한 독립 검토는 [검토 기록](REVIEWS.md), 재현 자료는 [검증 근거](../evidence/role4_build_validation.json)에 있다.

**결과:** 참조 정류장 464개, 학습 수요 완전 관측 454개, 미관측 10개를 유지했다. 원본 거리 보유 292개를 연결하고 비대각 129,860개 미확보 값은 그대로 `null`이다. 42개 중앙차로는 삭제하지 않고 정책 표시로 분리했다. 비중앙차로·완전 수요·거리 보유를 만족하는 259개는 진단 부분집합으로만 명시했다.

**해석:** 전체 기준의 지도·수요 표현과 부분 거리 인계는 가능하다. 그러나 전체 지역의 수요·도로 입력이 완전하다는 결론은 기각하며 `full_district_model_ready=false`를 유지한다. 가까운 역 기준점, 유한한 도로비용, 정차 가능성 및 실제 운행 효과는 서로 다른 사실이다.

**한계·후속 과제:** 일관된 전체 도로망과 방향별 스냅·비용을 추가 확보하고, 원천 기록 없는 10개 및 정류장 이력을 조사해야 한다. 실제 출입구·보행·회전·정차 검증은 남아 있다. 부분집합을 전체 후보로 바꿔 성능을 보고하거나 결측을 0으로 채우는 후속 사용은 이 연구 해석에 부합하지 않는다.
