# 도로거리 확장의 연구 방법과 남은 한계

## 연구 질문

기존 연구 지역 808개의 거리 자료를 공식 서대문구 ARS 코드 13 정류장 464개에 연결했을 때, 전체 정류장 간 방향별 도로비용을 제공할 수 있는가?

## 관측 자료와 분석

기존 두 ZIP의 `from_station_id`, `to_station_id`, `road_m`을 공식 정류장 ID에 결합한다. 원본 행렬의 모든 방향별 수치를 유지하며 대칭화·직선거리 대체·0m 보정은 하지 않는다. 모든 464개 ID를 동일 순서로 보존하고 관측이 없는 비대각 성분은 `null`로 표현한다. 대각선 0은 같은 정류장에 머무르는 수학적 항등비용이며, 그 정류장에 도로자료가 있다는 뜻은 아니다.

새로운 전체 도로비용을 만들기 위해 전체 정류장 경계에 남북 약 2km·동서 약 2km 여유를 둔 OSM 도로망 취득을 검토했다. 새로운 그래프를 만들 경우 기존 비용과 섞지 않고 독립 버전으로 제공해야 한다. 도로 중간 노드, 방향, 간선 투영과 오프셋, 같은 간선의 순방향 이동, 연결 비용을 보존해야 한다. [OSM oneway 정의](https://wiki.openstreetmap.org/wiki/Key:oneway), [접근 제한](https://wiki.openstreetmap.org/wiki/Key:access), [Overpass API](https://wiki.openstreetmap.org/wiki/Overpass_API)를 확인했다.

이번 취득으로는 도로망 원문이 확보되지 않아 새 전체 그래프·Dijkstra 계산은 수행하지 않았다. 따라서 새 그래프 방식의 정확성이나 464개 전체 연결성을 입증하지 않는다. 실제 제공 자료는 원본 거리의 부분 참조 행렬이다.

## 결과와 해석

원본 자료는 공식 정류장 464개 중 292개를 포함하고, 이 292개 사이 방향별 84,972개 비용을 제공한다. 전체 464개에는 방향별 214,832개 비용이 필요하므로 129,860개가 미확보다. 이는 이동 불가 판정이 아니라 관측자료 부재다.

`112900003 → 112900157`은 원본 도로거리 0m, 원본 직선거리 24.4m다. 원래 스냅의 끝점·시작점이 같은 도로 노드를 공유하는 근사에서 비롯된 것으로 설명되지만 실제 서로 다른 정차 위치 사이의 도로 이동이 0m임을 검증한 것은 아니다. 원본값과 품질 경고를 함께 보존한다.

공식 목록의 ARS 구분은 코드에 따른 연구 모집단이다. 행정경계 폴리곤 내 포함을 별도로 검증한 것은 아니며, 서로 다른 시점의 정류장·도로 자료 사용 한계도 남는다. 중앙차로 제외 등의 정차 가정은 거리 원본 자체를 삭제하거나 바꾸는 방식으로 적용하지 않는다.

- [데이터 변환 코드](../../scripts/build_role4_roads.py).

```powershell
python scripts/build_role4_roads.py
python -m pytest tests/test_role4_roads.py
```

기존 모델은 숫자만 있는 거리 행렬을 전제로 하므로 이 `null` 포함 자료를 그대로 입력하면 안 된다. 전체 지도의 정류장·수요 표현과 전체 지역의 모델 투입 준비 상태를 구별해야 한다. 292개 관측 부분집합을 별도로 전달할 수 있지만 이를 전체 지역 확장 완료로 표현하지 않는다.

## 후속 연구 과제

464개 전체의 독립적인 도로망 취득 및 재현 가능한 방향별 스냅·최단거리 구축이 필요하다. 스냅 오차, 같은 간선 이동, 일방통행, 회전·유턴, 사유도로·단지 내부 접근성은 별도 확인 대상이다. 임의 직선거리로 빈 비용을 채워 완전한 거리 행렬이라고 주장하지 않는다. 모델·노선 탐색 성능 실험은 이 분석의 범위가 아니다.
